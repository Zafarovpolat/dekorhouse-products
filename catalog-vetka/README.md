# DEKOR MARKET — Каталог VETKA

Печатный каталог категории **«Декоративные цветочные ветки»**. A4 landscape, 58 страниц.
Дизайн один в один с каталогом ZELEN (`../catalog/`), отличаются только тексты и данные.

## Что внутри

| Файл | Что это |
|---|---|
| `index.html` | вёрстка, сама строит все страницы из products.json |
| `products.json` | 250 товаров: код, цена, картинка |
| `img/` | 248 подготовленных картинок |
| `logo.png` | логотип |
| `build-pdf.py` | HTML → PDF через headless Chromium |
| `fix-pdf.py` | лечит ICC от Chromium и делает ebook-версию (замена ghostscript) |
| `catalog-vetka-printer.pdf` | печатная версия, 34 МБ |
| `catalog-vetka-ebook.pdf` | облегчённая, 15 МБ — для телефона и мессенджеров |

## Что пришлось сделать технически

**Битые ссылки.** У 57 товаров картинка в базе указана на `cdn.bito.uz`, а этот хост
отдаёт HTML админки вместо картинки. Рабочий адрес — `api.bito.uz/upload-api/public/uploads/...`.
В базе ссылки не менялись, подстановка только при сборке каталога.

**Группировка серий.** В этой категории разделитель в коде бывает и дефисом, и пробелом
(`B-1-blue`, `B-2 green`, `Z-20 rose pink`). Регексп из ZELEN ловил только дефис, из-за чего
84 товара из 250 выпадали из своих серий. `seriesKey()` расширен.

**Фон картинок.** У 164 вырезок фон был чисто белый (255), а фон документа `#fafafa` (250) —
на странице это давало видимую белую плашку, что запрещено регламентом (`PROJECT_CONTEXT.md`).
Фон приведён к `#fafafa` заливкой от краёв кадра, поэтому белые цветы в середине не задеты.

**Размер.** Сырой PDF на полноразмерных картинках весил 204 МБ, а ghostscript в среде сборки
недоступен. Картинки заранее приведены к 1400 px по длинной стороне и JPEG q88: 210 МБ → 34 МБ.
Форма, цвет и кадрирование товара не менялись — только масштаб и подложка фона.

## ❗ Почему картинки не открывались на телефоне и как это вылечено

Это та самая поломка, о которой предупреждает `PROJECT_CONTEXT.md`, и она
воспроизвелась здесь в полном виде.

Chromium при печати в PDF заворачивает **каждую** картинку в цветовое
пространство `/ICCBased`. В свежесобранном каталоге таких было 256 из 256,
а `/DeviceRGB` не встречался ни разу. Часть мобильных PDF-viewer'ов
(Adobe Reader на Android, отдельные браузеры на iOS) такие ICC-профили не
переваривает и **просто не рисует картинки** — при том что на десктопе
всё прекрасно видно. Плюс Chromium дописывает `/ColorTransform` к JPEG-потокам,
что добавляет декодеру неоднозначности.

Раньше это лечил ghostscript (`-dColorConversionStrategy=/sRGB`). Здесь его в
среде сборки не было, поэтому `fix-pdf.py` делает то же самое напрямую через
pikepdf/qpdf:

- `/ColorSpace [ /ICCBased N ]` → `/DeviceRGB` (или `/DeviceGray` для одноканальных);
- удаляет `/ColorTransform`;
- для ebook-версии дополнительно пережимает JPEG-потоки.

Картинки готовятся как обычный sRGB JPEG без встроенного профиля, поэтому
ICC-обёртка не несла никакой информации: печатная версия после починки
**попиксельно идентична** исходной (проверено, максимальное отличие 0).
У ebook отличия только от пережатия JPEG и на глаз не видны.

Итог: `ICCBased` 256 → 0, `DeviceRGB` 0 → 256, `ColorTransform` 248 → 0,
все 256 картинок декодируются без ошибок.

## Как пересобрать PDF

```bash
pip install playwright pypdf pikepdf pillow
python3 -m playwright install chromium

cd catalog-vetka
python3 build-pdf.py        # → catalog-vetka.pdf (сырой, на телефоне картинки не покажет)
python3 fix-pdf.py          # → catalog-vetka-printer.pdf + catalog-vetka-ebook.pdf
```

**Отдавать клиенту только результат `fix-pdf.py`.** Сырой `catalog-vetka.pdf`
промежуточный, в репозитории не хранится.

## Как менять содержимое

Титул, даты, контакты, название категории — блок `window.CONFIG` в `index.html`.
Там же оба блока контактов: розничный и B2B/опт.
Товары и цены — `products.json`. Раскладка страниц — `planPages()`: минимум 3
карточки на страницу, максимум 6, серия держится на одной странице.
